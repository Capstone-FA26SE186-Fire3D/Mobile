# Unity Android integration (#11–#13, #22)

`unity-artifact.lock.json` is deliberately unpinned until Unity supplies the Android `unityLibrary` export. Fill its `version`, `s3Uri` (`s3://bucket/.../<version>/unityLibrary.zip`) and lowercase archive `sha256` from the handoff. Do not commit credentials or the export. Run `pnpm unity:prepare` with an AWS CLI identity allowed to read that object, then `pnpm android:prebuild`. The script verifies the archive hash before extracting it into ignored `vendor/unityLibrary`; the Expo config plugin verifies that cache and copies it into generated Android during each clean prebuild. Native config requires ARM64 and minSdk 29.

The package verifier accepts only `fet3d.package/1`, Android, runtime `2.0.0`, pinned Building/revision/material library and the BE manifest SHA-256. It verifies every listed file before placing the package under the release ID and manifest hash in private app storage. Current BE `POST /api/training/sessions` pins `packageHash`/`manifestHash` but does **not** return a signed manifest URL and per-file download URLs. `launchTrainingSession` therefore requires a `PackageDownload` argument and has no UI caller until BE publishes that contract. It never guesses a storage URL.

The local Android module implements `com.fet3d.unity.Fire3DUnityBridge.onUnityMessage(String)` and writes each callback to native SQLite before notifying JavaScript. JavaScript copies callbacks to its own SQLite event queue before acknowledging native records. `/events:batch` sends at most 500 events, marks accepted/duplicate IDs, retains missing ranges and makes conflicts nonretryable. Completion keeps one idempotency key and treats `AwaitingSync` as pending. Launch requests contain protocol `1`, no grant, and use the generation only for `/launched`.

The integration gate remains open until Unity supplies a sample export and package, adds `Fire3DApp.Resume`, and changes `SessionEventLog.TakeBatch`/`Fire3DBridge.Send` so a callback storage failure can be retried. Android build and repeated Unity teardown have not been run without that artifact. BE must enable live launch and supply the signed package URL contract; the mock or TypeScript checks are not Android acceptance.
